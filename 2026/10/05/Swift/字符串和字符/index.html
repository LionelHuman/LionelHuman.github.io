Swift 字符串与字符：从“看起来简单”到“编译器教你做人”

毕竟，字符串不就是一串字符吗？在别的语言里，str[0] 就是第一个字符，这有什么难的？

然后他们写了 let firstChar = myString[0]，接着编译器毫不留情地甩出一个红红的错误：'subscript(_:)' is unavailable: cannot subscript String with an Int。

那一刻，很多人的内心是崩溃的：“我就想拿个第一个字符，为什么这么难？”

说句实在话，Swift 的 String 和 Character 是整个语言里最复杂的类型之一

复杂的原因不是它故意刁难你，而是因为它必须完美处理 Unicode

特殊字符怎么打？

我们平时写代码，经常需要用到转义字符。Swift 里常见的转义包括 \n（换行）、\t（制表符）、\\（反斜杠本身）以及 \"（双引号）。

这里要重点讲一个很多人一开始不明白的特性：Swift 里的 String 是值类型。

这句话是什么意思呢？就是你把这个字符串赋给另一个变量，或者传给一个函数时，传递的是这个字符串的“副本”，而不是它本身的引用。

🚨 避坑指南：别再担心性能问题

很多从 Objective-C 过来的人，一听到“值类型拷贝”就本能地担心性能：“每次传值都拷贝，那如果字符串有 10MB 大，内存不就炸了？”

放心，Swift 的编译器非常聪明。在底层，它运用了“写时复制”（Copy-on-Write）技术。在你真正去修改 str2 之前，str1 和 str2 底层指向的是同一块内存。只有在发生了修改操作时，它才会真正分配新内存进行拷贝。所以，你可以大胆地把字符串当做值类型来用，完全不用操心性能。

字符与 Unicode：为什么你的字符串长度总是算不对

一旦你开始处理中文、Emoji，甚至带重音符号的英文，你原来的“字符串就是字符数组”的认知就会彻底崩塌。

Swift 里的 Character 类型，代表的是一个扩展字形簇（Extended Grapheme Cluster）。听起来很玄乎，其实意思就是：一个人类肉眼看到的字符，可能底层是由多个 Unicode 标量拼出来的。

比如，字母 é：

  • 它可以是一个单独的 Unicode 标量 \u{E9}
  • 它也可以是一个普通的字母 e (\u{65}) 加上一个重音符号 ´ (\u{301})

在 Swift 里，这两种写法被认为是同一个字符，都是 1 个 Character。

更极端的例子是 🇺🇸 这个美国国旗 Emoji，它其实是由两个 Unicode 标量拼成的，但在 Swift 里它就是一个字符。
