Swift 控制流：别让 if-else 堆砌成山，掌握这几种姿势就够了

刚学编程的时候，很多人写代码就像在写流水账，从上到下，一条路走到黑

遇到需要“根据不同情况做不同处理”或者“重复做某件事”的时候，就开始疯狂地嵌套 if-else，或复制粘贴十遍相同的代码

回首望去，可能会发现某个循环里忘了递增变量，导致程序直接卡死；或者写 switch 时习惯性地敲了个 break，结果编译器告诉你这多余了

Swift 的控制流，就是用来解决这些问题的，它提供了一套非常现代、安全且表达力极强的语法

for-in 是 Swift 里最常用的循环

只要一个类型遵循了 Sequence 协议，数组、字典、范围、字符串都符合Sequence协议，你就可以用 for-in 遍历它

避坑指南：别在遍历时修改集合
如果你在 for-in 循环里修改数组（比如删除或添加元素），会直接导致运行崩溃
如果需要修改，请使用传统的索引遍历，或者创建一份副本进行遍历

while 循环：当循环次数未知时

for-in 适合你知道要循环多少次的情况，但有些时候，你只知道“只要条件成立，就一直做”。这时候就用 while

比如写一个最简单的回合制游戏逻辑：只要玩家还没走到终点，就一直掷骰子

while 是在每次循环开始前检查条件

while它有一个兄弟叫 repeat-while，它是在每次循环结束后检查条件，这意味着循环体至少会执行一次

避坑指南：警惕死循环
写 while 时，一定要确保条件最终会变成 false
如果忘了递增变量，或者条件永远为真，程序就会卡死。在终端里按 Control + C 才能强制停止

while 和 repeat-while 区别

对比维度 while 循环 repeat-while 循环
执行顺序 先判断条件，后执行循环体 先执行循环体，后判断条件
核心特点 条件不成立时，一次都不执行 循环体至少会执行一次
使用场景 循环次数可能为 0 的情况 无论条件如何，都要先做一次基础操作的情况
代码示例 如果一开始 square >= 25，diceRoll 和 print 不会执行 即使一开始 square >= 25，也会执行一次内部逻辑
  1. while 循环：先判断，后执行

逻辑：每次进入循环体之前，先问自己“条件成立吗？”如果成立，就做；如果不成立，一次都不做，直接跳过

使用场景：循环次数可能为 0 的情况

结合你的第一个例子：如果一开始 square 就大于等于 25，那这个循环里的 diceRoll 和 print 一次都不会执行

  1. repeat-while 循环：先执行，后判断

逻辑：先进去把活干了，干完之后再来问“条件还成立吗？”如果成立，回去继续干；不成立，结束

核心特点：循环体至少会执行一次

使用场景：无论条件如何，我都要先做一次基础操作

💡 用大白话打个比方：

while 就像进门前先刷卡：你走到门口（循环开始前），先刷卡（检查条件），如果卡里没钱（条件不成立），门打不开，你转身就走，连门都进不去（循环体一次都不执行）。
repeat-while 就像先试吃再决定买不买：你走到摊位前，不管怎样先拿一块试吃（执行一次循环体），吃完再决定（检查条件）。如果觉得好吃（条件成立），再买一块（继续循环）；如果觉得不好吃（条件不成立），走人（结束循环）。但无论如何，你至少已经试吃过一次了。

if 和 switch：分支逻辑的抉择

if 是大家最熟悉的。简单的条件判断、范围判断，用 if 就很合适

如果有一大堆互斥的条件，判断一个分数属于哪个等级，还用 if-else 堆叠就会很痛苦。这时候，switch 就是更好的选择

Swift 的 switch 有一个巨大的优势：它默认不会“贯穿”（fall through）。
C 语言里，如果你忘记写 break，代码会继续执行下一个 case
Swift 直接把这个坑给你填了——匹配到一个 case 后，执行完就结束，不需要写 break，写了也没错，只是多余

另外，Swift 的 switch 必须穷尽所有可能。如果你无法列出所有情况，必须写 default。

避坑指南：不要写空的 case
Swift 不允许 case 里面没有可执行语句。如果你只想匹配但什么都不做，必须显式写一个 break。

if 表达式：Swift 5.9 后的新写法

如果需要根据条件给变量赋值，以前你可能要先声明变量，然后在 if-else 里分别赋值

从 Swift 5.9 开始，你可以直接用 if 表达式来简化这个流程。

注意，if 表达式的每个分支必须返回相同类型的值，并且必须穷尽所有条件（要么有 else，要么覆盖所有可能）
2025-2026 年的新项目，可以放心使用这个特性。

guard 与 defer：优雅地处理提前退出和清理

guard 是 Swift 里非常独特且实用的关键字。它和 if 类似，但要求条件必须为真，否则就会执行 else 里的代码并退出当前作用域。

为什么用它？因为它能极大减少 if-let 带来的嵌套地狱。很多新手写函数，会写成这样：

在 guard 之后，name 和 location 都是非可选的常量，可以直接使用，而且作用域覆盖了后面的所有代码。这就是所谓的“提前退出”。

defer 则是用来处理“离开作用域前必须执行的操作”。比如你要打开一个文件，处理完后必须关闭它，这时可以用 defer。

注意，defer 的执行顺序是后进先出（LIFO）。如果你在同一个作用域写了多个 defer，最后写的会最先执行。

控制转移语句：continue、break 和 fallthrough

  • continue：在循环中跳过本次迭代，直接进入下一次迭代。比如在过滤字符串时，遇到元音就跳过。
  • break：在循环中直接终止整个循环；在 switch 中用于忽略某个 case。
  • fallthrough：这是为了兼容 C 语言的风格而存在的。Swift 默认不贯穿，但如果你真的想执行完当前 case 后继续执行下一个 case，可以用 fallthrough。不过在实际开发中，几乎不会用到它，建议新手先忘掉它。
