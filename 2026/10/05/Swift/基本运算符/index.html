Swift 基本运算符：那些年新手必踩的坑，和必须搞懂的细节

我见过太多刚学 Swift 的人，在写代码时遇到 if x = y 被编译器无情报错，或者莫名其妙在 let b = a += 2 这里卡了半天

很多时候不是逻辑有多难，而是你根本不了解 Swift 在“运算符”上做了多少安全妥协。

很多语言（比如 C 或 Objective-C）的运算符很自由，但也很危险，Swift 的设计哲学是“把问题扼杀在编译阶段”

取余运算符 % 其实叫“余数运算符”

9 % 4 等于 1，因为 9 里面最多能放两个 4，余下 1。这个很好理解。但在 Swift 里，负数的取余和你在数学课本上学的“模运算”有点区别：

为什么？ 因为 Swift 的 % 计算的方程是 a = (b x 某个倍数) + 余数。对于 -9 % 4，-9 = (4 x -2) + (-1)，所以余数是 -1。而且 Swift 会忽略除数 b 的符号，a % b 和 a % -b 结果永远一样。

避坑指南：Swift 默认禁止数值溢出

在 C 语言里，如果 Int8 最大值（127）再加 1，它可能会默默地变成 -128（循环溢出）。但在 Swift 里，算术运算符默认会检测溢出，一旦溢出，程序直接崩溃报错。

如果你确实需要溢出行为（比如做底层计算或加密算法），必须明确使用溢出运算符，比如 a &+ b。把风险摆在明面上，这也是 Swift 安全性的体现。

避坑指南：短路求值

如果 a 不是 nil，那么 b 根本不会被计算。这叫短路求值。这在 b 是一个耗时操作（比如网络请求、复杂计算）时非常有优势。但要注意，如果你依赖 b 的副作用（比如修改了某个变量），那你可能会被这个特性坑到。

另外，?? 是处理 Optional 的优雅方式，比 a! 强制解包安全得多。新手期尽量多用 ?? 和 if let，少用 !。

你可以遍历 2... 或 ..<2，但不能遍历 ...2，因为编译器不知道迭代应该从哪里开始。另外，像 let range = ...5 这种单边范围，可以用来检查包含关系（range.contains(7) 返回 false），但不能用来无脑循环，因为它是无限延伸的，容易造成死循环。

逻辑运算符：短路求值与括号的力量

Swift 支持三种逻辑运算符：非（!a）、与（a && b）、或（a || b）。它们都只操作 Bool 值。

非（!）：反转布尔值。

与（&&）：两个都为 true，整体才为 true。如果第一个是 false，第二个根本不会被计算（短路求值）。

或（||）：只要有一个为 true，整体就为 true。如果第一个是 true，第二个不会被计算。

避坑指南：左结合与显式括号
