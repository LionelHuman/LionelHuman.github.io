Swift 基础不“基础”：从 The Basics 开始，把安全写进代码里

我写了这么多年 Apple 平台代码，回头看 Swift 官方文档里的 The Basics，最深的感受是：真正决定你后面走得多稳的，不是 SwiftUI 那些花哨的动画，也不是架构模式，而是这些看起来最简单的东西——常量、变量、类型、Optional、错误处理、断言。

很多新手学 Swift 卡住，不是因为 Swift 难，而是因为一开始就跳过了这些“基础”，直接去写界面。

结果就是：能照着教程抄出一个页面，但遇到一个 Int? 就不知道怎么办，遇到网络错误就只会 print，遇到状态不对就到处加 if。

我想带你从 The Basics 出发，由浅入深地把 Swift 的地基打牢

你不需要有编程经验，但需要有一点耐心。每读一段，最好打开 Xcode 或 Swift Playgrounds，把代码敲一遍。

Swift 为什么把安全放在第一位

Swift 官方文档一开头就强调：Swift 是一门安全的语言。它的安全体现在两个层面：类型安全和内存安全。

类型安全的意思是，如果你的代码需要 String，Swift 不会让你误传一个 Int

内存安全的意思是，Swift 尽量保证你不会读到未初始化的内存、不会越界访问数组、不会使用已经释放的对象，也不会在并发代码里随便产生数据竞争。

这些检查大部分在编译时完成，有些会在运行时完成，对新手来说，这听起来可能有点抽象

可以这样理解：Swift 在帮你提前抓错。很多在其他语言里要等到运行时才崩溃的问题，Swift 在编译阶段就拦住了。

Swift 的基础类型包括：

  • Int：整数
  • Double：浮点数
  • Bool：布尔值
  • String：文本
  • Array、Set、Dictionary：三种主要集合类型

此外还有元组、Optional 等高级但常用的类型。下面我们一个个来。

整数：Int、UInt 和整数边界

整数是没有小数部分的数字，比如 42 和 -23。整数分有符号和无符号，有符号可以是正数、零或负数，无符号只能是正数或零。

Swift 的整数类型名字里会带上位数和符号：

  • UInt8：8 位无符号整数
  • Int32：32 位有符号整数
  • Int：跟随平台字长的整数
  • UInt：跟随平台字长的无符号整数

你可以访问每种整数类型的最小值和最大值：

在大多数情况下，你不需要指定整数大小，直接用 Int 就好。Int 在 32 位平台上是 Int32，在 64 位平台上是 Int64。即使 32 位平台上，Int 也能存下 -2,147,483,648 到 2,147,483,647，足够日常使用。

UInt 只在特定需要无符号整数且与平台字长一致时使用。其他时候，即使你知道值不是负数，也优先用 Int。这样代码互操作性更好，也能匹配 Swift 的整数类型推断。

整数运算通常产生精确结果，所以适合计数、分数、价格等需要精确计算的场景。但注意：如果计算结果超出范围，程序会停止执行，而不是存一个无效值。你也可以显式使用溢出运算符，但那是更后面的内容。

浮点数：Double、Float 和精度问题

浮点数有小数部分，比如 3.14159、0.1、-273.15。

Swift 提供多种浮点类型：

  • Double：64 位，默认选择
  • Float：32 位
  • Float16、Float80：特定平台或场景

如果你不需要指定大小，用 Double。Swift 在推断浮点数时，也总是优先选择 Double。

浮点数能表示很大和很小的数，但不能表示范围内所有值。浮点运算会舍入到最近的可表示值。比如 Float 存储 10,000 后，下一个更大值可能是 10,000.001。大数之间的间隔通常比小数之间的间隔大。

浮点数还有负零、正无穷、负无穷和 NaN。NaN 表示无效或未定义结果，比如 0 除以 0。整数遇到无法表示的结果会停止程序，浮点数则可能产生这些特殊值。

如果你需要所有值之间等距，或者需要精确结果，浮点数可能不是正确选择，可以考虑定点数。

内存安全：Swift 在背后帮你挡住什么

Swift 除了类型安全，还提供内存安全。官方文档列出了几个要求：

  • 值在读取前必须设置，这叫明确初始化。
  • 数组和缓冲区只能通过有效索引访问，这叫边界安全。
  • 内存只能在值的生命周期内访问，这叫生命周期安全。
  • 内存访问重叠只能以可证明安全的方式发生，这叫线程安全。

如果你用过不提供这些保证的语言，可能遇到过未初始化内存、数组越界、释放后使用、数据竞争等问题。Swift 的安全代码会尽量避免这些问题。

但 Swift 也提供一些不安全 API。当你看到名字里带 unsafe、unchecked、unmanaged 的类型或方法时，你要自己承担安全责任。

安全代码仍然可能遇到错误和意外失败。安全不代表程序一定运行到结束。Swift 提供错误处理、断言和先决条件来应对不同情况。

新手常见坑

  • 把该用 let 的地方写成 var。先写 let，编译器报错再改 var。
  • 一看到 Optional 就加 !。强制解包是运行时炸弹，优先用 if let、guard let、??。
  • 忽略类型推断，写一堆多余的类型注解。有初始值时，让 Swift 推断。
  • 用 UInt 存所有非负数。大多数时候用 Int。
  • 用浮点数做精确金额计算。金额可以考虑整数分或定点数。
  • 把元组当复杂数据结构。复杂结构用 struct 或 class。
  • 用 assert 处理用户输入错误。断言用于开发期检查，不是用户错误处理。
  • 不写注释。注释要解释“为什么”，而不是重复“是什么”。

下一步：从 Swift 基础走向 SwiftUI

如果你已经能理解这篇博客里的代码，并且亲手敲过一遍，那么你已经有了继续往下走的底气。

接下来我建议你按这个顺序走：

  • 用 Swift Playgrounds 继续练基础语法和 Optional。
  • 读苹果官方《The Swift Programming Language》的 The Basics、Collection Types、Control Flow、Functions、Optionals。
  • 开始 100 Days of SwiftUI，用项目驱动学习。
  • 学 SwiftUI 的 View、@State、List、NavigationStack。
  • 做一个小 App，比如待办清单、单位转换器、记账雏形。
  • 再学网络、SwiftData、MVVM、并发和测试。
  • 最后把一个小工具上架 App Store。

Swift 的基础不会限制你，反而会托住你。你越早把 let、var、类型、Optional、错误处理和断言这些概念用熟，后面写 SwiftUI 就越不容易被状态和异步搞晕。

别急着做复杂的 App。先写一个能跑通的小例子，再写一个能保存数据的小页面，最后写一个能上架的小工具。一步一步来，这条路很长，但每一步都算数。
