MySQL 8.0 从零到一：CentOS Stream 9 二进制安装、脚本封装与多实例实战

本文面向刚接触数据库的新手，从数据库基本概念讲起，逐步深入到 MySQL 8.0 在 CentOS Stream 9 上的二进制安装、Shell 脚本封装、多实例配置以及常见问题处理。全文案例齐全，可直接照做。

为什么要把 MySQL 5.7 升级到 8.0？

很多公司早期业务跑在MySQL 5.7上，稳定运行了几年。但随着业务扩展，5.7逐渐力不从心：

  • 新功能依赖 8.0：窗口函数、CTE、JSON 增强、角色管理等，5.7 都没有。
  • 性能与一致性：5.7 存在一些已知 Bug，影响查询性能和数据一致性。
  • 官方支持到期：MySQL 5.7 已于 2023 年 10 月 EOL，不再获得安全更新。

因此，迁移到 MySQL 8.0是大势所趋。本文就以 MySQL 8.4.0（GA 版本）为例，手把手带你完成在 CentOS Stream 9 上的安装部署。

数据库与 MySQL 基础速览

数据库是什么？

数据库就是存储数据的仓库，本质是文件系统，按特定格式组织数据，支持增删改查。它能结构化存储大量数据，保证一致性、完整性，读写效率极高。

关系型 vs 非关系型

  • 关系型数据库：采用二维表（行和列）组织数据，如 MySQL、Oracle、SQL Server。数据通常存硬盘，安全但速度相对慢。
  • 非关系型数据库（NoSQL）：以 Key-Value 形式存储，如 Redis、MongoDB。多存内存，速度快但安全性相对低。

MySQL 简介

MySQL是开源免费的关系型数据库管理系统，跨平台，支持事务、主从复制、多种存储引擎。

MySQL被Oracle收购后，社区分叉出MariaDB。我们日常说的MySQL通常指Oracle MySQL社区版。

MySQL采用C/S架构：客户端（Client）发起请求，服务器端（Server）处理

服务器上运行一个或多个MySQL实例，每个实例管理多个数据库，每个数据库包含多张表。

MySQL 安装方式对比

安装方式 优点 缺点
yum 安装 简单，自动处理依赖 可定制性差，数据目录固定
二进制安装 灵活，可自定义路径和参数 需手动初始化，步骤稍多
源码编译安装 可定制性最强 安装复杂，耗时长

新手推荐二进制安装，既能自定义，又不像源码编译那么繁琐。

从 MySQL 5.7 迁移到 8.0 的建议

  • 使用 mysqldump 全量备份 5.7 数据。
  • 用 MySQL Shell 的 util.checkForServerUpgrade() 做升级检查。
  • 在测试环境先导入验证，注意字符集、认证插件、SQL_MODE 变化。
  • 生产环境灰度切换，准备好回滚方案。
