虚拟机克隆与资源分配：赢在起跑线

搭建集群的第一步是准备机器。很多新手喜欢用ISO镜像从头安装三台Linux，这不仅浪费时间，还容易因为安装过程中的微小差异导致后续配置出错

我强烈推荐你直接克隆一台已经配置好基础系统的虚拟机。但在克隆之前，被克隆的虚拟机必须处于关机状态

创建完整克隆后，你的node2和node3就拥有了和node1完全一致的系统环境

Windows宿主机上同时跑三台虚拟机，内存和CPU的规划至关重要

假设你的物理机有16G内存，建议给每台虚拟机分配4G，刚好占满且不留余地；CPU每台建议分配2核

千万不要把内存分得太抠门，Hadoop的NameNode和DataNode都是内存大户，内存不足会导致频繁的GC甚至OOM崩溃

内存分配经验公式

每台虚拟机内存 = 物理机总内存 ÷ 4 （3台虚拟机 + 1台宿主机）

例如物理机16G，则每台虚拟机分配4G，CPU每台2核

网络与身份标识：让每台机器独一无二

克隆出来的虚拟机虽然系统一致，但网络身份是冲突的

因为它们的MAC地址完全相同，如果不重新生成，在同一局域网内就会出现IP冲突或无法获取网络的情况

在VMware的设置里，务必为node2和node3点击“重新生成MAC地址”

安全策略与远程连接：打通机器间的壁垒

在学习阶段，Linux的防火墙和SELinux往往是最大的“拦路虎”。

我曾遇到过一个经典案例：Hadoop集群启动正常，但Web UI死活打不开，远程连接也时断时续，最后发现是防火墙拦截了端口

为了减少不必要的排错成本，建议在学习环境中直接关闭它们。

同时，编辑 /etc/selinux/config，将SELinux设置为 disabled

SELinux是Linux的安全子系统，有enforcing、permissive、disabled三种模式，但在搭建大数据集群时

它的严格权限控制会干扰很多跨节点操作，关闭它能省去大量麻烦。修改后记得 reboot 重启生效。

SSH免密登录：分布式通信的基石

大数据集群的核心是“分布式”，节点之间需要频繁通信。如果每次交互都要输入密码，不仅效率低下，自动化脚本也无法运行

SSH免密登录的原理是公钥私钥的挑战应答机制，可以拆成五步来理解：先在B节点配置A节点的公钥，A节点发起登录请求，B节点用公钥加密一段随机文本发给A节点，A节点用自己的私钥解密后回传，B节点验证文本是否正确，通过即允许登录。

第一步，在三台机器上分别生成密钥对，连续按三次回车即可，默认在 /root/.ssh 下生成id_rsa私钥和id_rsa.pub公钥。

第二步，在三台机器上把公钥汇总拷贝到node1

第三步，把node1上汇总好的认证文件分发到node2和node3。完成后，从任意一台机器 ssh node2 测试，如果无需密码即可登录，输入exit退出，就说明免密配置成功。

第三步：把node1汇总的认证文件分发到node2、node3

时钟同步：分布式系统的隐形生命线

在分布式系统中，时间不一致是致命的。很多分布式系统是有状态的，比如同一条数据，A节点记录的时间是1，B节点记录的时间是2，后续逻辑就会乱套。Hadoop的很多机制依赖时间戳，比如心跳检测、日志排序、数据块过期清理等。如果节点间时间相差几秒，就可能导致NameNode误判DataNode宕机，或者任务调度出现诡异的重试。

时钟同步有两种方式。如果你的集群能联网，最简单的方法是配置crontab定时任务，每分钟从阿里云时间服务器同步一次。

键入以下内容：每隔一分钟连接阿里云时间同步服务器

如果处于内网环境，就需要以node1作为时间服务器。在node1上安装ntp服务并启动，关闭chrony，设置开机自启；编辑 /etc/ntp.conf 授权本网段同步，注释掉外网server，启用本地时钟兜底；再保证BIOS与系统时间同步；最后重启ntpd。node2和node3则通过crontab每分钟向node1同步时间。

在node1上安装并启动ntp服务

yum -y install ntp
systemctl start ntpd
systemctl disable chrony # 关闭chrony，避免与ntpd冲突
systemctl enable ntpd # 设置ntpd开机启动

编辑node1的/etc/ntp.conf

vim /etc/ntp.conf
restrict 192.168.88.0 mask 255.255.255.0 nomodify notrap # 授权本网段

server 0.centos.pool.ntp.org # 集群走内网，注释掉外网时间源

server 1.centos.pool.ntp.org

server 2.centos.pool.ntp.org

server 3.centos.pool.ntp.org

server 127.127.1.0 # 断网时用本地时钟兜底
fudge 127.127.1.0 stratum 10

保证BIOS与系统时间同步

vim /etc/sysconfig/ntpd
SYNC_HWLOCK=yes

systemctl restart ntpd

在node2、node3上配置定时向node1同步

crontab -e
/1 ** * /usr/sbin/ntpdate 192.168.88.161
基础设施软件：MySQL与JDK的标准化部署
环境统一后，就可以安装基础软件了。MySQL通常只需要在node1上安装，用于存储Hive等组件的元数据。要先检查系统自带的MySQL，如有则卸载干净；然后在线下载mysql80-community-release的rpm包并安装，得到指定版本的repo配置文件；编辑 /etc/yum.repos.d/mysql-community.repo，把目标版本的 enabled 设为1、把不需要的高版本 enabled 设为0，避免版本冲突；最后用yum一次性拉取客户端、服务端和开发工具包。启动服务并设置开机自启后，登录后开启远程访问权限。

查看并卸载系统自带MySQL

rpm -qa | grep mysql
rpm -e –nodeps mysql-libs-5.1.73-8.el6_8.x86_64

在线获取CentOS7的mysql rpm源并安装

wget https://repo.mysql.com//mysql80-community-release-el7-1.noarch.rpm
rpm -ivh mysql80-community-release-el7-1.noarch.rpm

修改下载配置文件，选定版本

cd /etc/yum.repos.d
vim mysql-community.repo # 目标版本 enabled=1，其余 enabled=0

在线下载安装客户端/服务端/开发包

yum -y install mysql-community-client mysql-community-server mysql-community-devel

启动服务并设置开机自启

systemctl start mysqld
systemctl enable mysqld

登录mysql（账号root，密码123456）

mysql -uroot -p123456

开启远程登录权限并刷新

grant all privileges on . to ‘root‘@’%’ identified by ‘123456’;
flush privileges;

如需彻底卸载

yum -y remove mysql-community-client mysql-community-server mysql-community-devel
这里要特别敲黑板：MySQL装完打不开远程连接，十有八九是防火墙没关或者没执行 flush privileges 刷新权限缓存，排查时优先看这两处。

JDK则是所有节点都必须安装的。作为绿色软件，我们只需解压并配置环境变量。先创建统一的软件目录和安装目录，把安装包上传后解压，再编辑 /etc/profile 配置 JAVA_HOME 等环境变量并重新加载。用 java -version 验证无误后，把JDK目录和profile文件分发到node2和node3，确保三台机器的Java环境完全一致——这也是后续Hadoop能一键分发、统一启动的前提。

创建统一目录

mkdir -p /export/software # 安装包存放目录
mkdir -p /export/server # 软件安装目录

上传jdk-8u241-linux-x64.tar.gz后解压

cd /export/software
tar -zxvf jdk-8u241-linux-x64.tar.gz -C /export/server

配置环境变量

vi /etc/profile # 光标移到最后，按i插入以下内容

set java environment

export JAVA_HOME=/export/server/jdk1.8.0_241
export CLASSPATH=.:$JAVA_HOME/lib/dt.jar:$JAVA_HOME/lib/tools.jar
export PATH=$PATH:$JAVA_HOME/bin

source /etc/profile # 重新加载环境变量
java -version # 验证是否安装成功

分发到node2、node3并在两机配置同样的环境变量后再验证

集群环境统一的底层心法
走完这一整套流程，你可能会觉得步骤繁琐，但这正是大数据集群稳定运行的底层心法：一致性、可追溯、自动化。环境统一不是为了好看，而是为了消除分布式系统里的“不确定性”。当所有节点的操作系统、网络配置、身份标识、时间、基础软件都完全一致时，任何异常都能被快速定位到代码或配置层面，而不是在底层环境的泥潭里反复打转。

把这条链路上的每个细节做扎实——克隆必关机、MAC必重生成、IP必静态、防火墙SELinux必关闭、SSH必免密、时钟必同步、软件目录必统一——你其实已经把分布式系统最朴素也最重要的工程哲学刻进了肌肉记忆。希望这篇指南能帮你打下坚实的地基，在后续搭建Hadoop生态时少走弯路。记住，优秀的架构师，都是从把每一台机器配置得一模一样开始的。
