  • node1 NameNode：http://47.112.206.241:50070 （状态应为 active）
  • node2 NameNode：http://47.112.211.215:50070 （状态应为 standby）
  • YARN 集群：http://47.112.206.241:8088/cluster
验证维度 验证命令 预期结果 意义
HDFS 主备 浏览器访问 node1 和 node2 的 50070 一个显示 active，一个显示 standby 验证 NameNode 双机热备
YARN 主备 在 node1 执行 yarn rmadmin -getServiceState rm1 返回 standby 或 active（根据当前选举） 验证 ResourceManager 双机热备
YARN 节点 浏览器访问任意 8088 Active Nodes 显示为 3 验证 3 台 NodeManager 全部成功注册
集群容灾 杀掉当前 Active 的 ResourceManager，观察另一台状态 另一台在几秒内自动变成 active 验证故障自动转移（HA 核心价值）

⚠️ 新手避坑指南（必看）

  1. yarn.resourcemanager.ha.id 绝对不能简单复制：在 node1 上该值为 rm1，当你把配置文件分发给 node2 时，务必在 node2 上把它改成 rm2，否则 YARN 的 ResourceManager 无法启动。
  2. 主机名和 FQDN 的选择：如果配置里用 node1.itcast.cn，而你的 /etc/hosts 只配了 node1，就会找不到地址。建议统一只写 node1、node2、node3。
  3. 启动顺序很重要：如果你是第一次部署，必须按上面的顺序：zkfc -> journalnode -> namenode format -> start-dfs -> bootstrapStandby -> start-all。如果直接 start-all.sh 报错，99% 是第一次没有初始化。
  4. HADOOP_HOME 环境变量：分发到 node2 和 node3 后，一定要再去这两台机器上 source /etc/profile，否则报 hadoop: command not found。

这 5 个问题，是本次实战中最值得记录的经验：

  1. 主机名映射：必须配置 /etc/hosts，且阿里云必须用内网 IP。
  2. ZooKeeper 端口：必须放行 2181、2888、3888，否则 ZKFC 初始化会失败。
  3. 分发配置文件要改差异化项：yarn-site.xml 的 ha.id 必须区分 rm1 和 rm2。
  4. JournalNode 顺序：必须先启动所有 JournalNode，再初始化 NameNode。
  5. Web UI 502 是正常现象：Standby 节点的 50070 和 8088 端口本身就是打不开的，不要怀疑自己。
