IP 地址 角色
172.22.223.0 master（控制平面）

硬件要求：每台至少 2 核 CPU、2GB 内存

推荐 CPU 4核、内存 8G

分类 项目 详细信息 / 状态
系统概览 主机名 master
操作系统 CentOS Stream 9
内核版本/架构/环境 Linux 5.14.0-731.el9.x86_64，x86_64，阿里云 KVM 虚拟机
硬件资源 CPU 4 逻辑核心，主频 2500MHz
内存 8 GiB，无 Swap 分区
网络配置 主网卡 eth0 IP: 172.22.223.0/20
SSH 服务 正常监听 22 端口

master主机IP 为 172.22.223.0，这在常规网络中通常是网络号，属于云厂商特殊分配的可用 IP。您之前 node1 的 IP 为 172.22.223.1，两者处于相同网段。

阿里云安全组特别提醒

如果是阿里云 ECS，务必在安全组入方向放行：

协议/端口 用途/说明
TCP 6443 API Server
TCP 10250 Kubelet
UDP 8472 Flannel VXLAN 通信 （← 极易漏掉，漏掉则 NotReady！）
TCP 30000-32767 NodePort 服务

确保三台机器分别是172.22.223.0 -172.22.223.2

核心踩坑记录与解决方案（实战经验）

坑1：kubeadm init 超时，API Server不健康

  • 现象：[api-check] The API server is not healthy after 4m0s
  • 原因：registry.k8s.io 无法访问，containerd 拉取 pause:3.10.2 镜像超时（i/o timeout）。
  • 解决：修改 /etc/containerd/config.toml 中的 sandbox 或 sandbox_image 为阿里云镜像；并在 kubeadm init 时增加 --image-repository registry.aliyuncs.com/google_containers。

坑2：Worker 节点加入后状态 NotReady

  • 现象：kubectl get nodes 中 node1、node2 始终为 NotReady。
  • 原因：Worker 节点没有配置镜像加速器，且 CNI 插件（Flannel）无法初始化网络。
  • 解决：在 Worker 节点也配置 docker.io 和 ghcr.io 的镜像加速；必要时清理 /var/lib/cni 并重启 containerd 和 kubelet。

坑3：Metrics Server 一直 ImagePullBackOff

  • 现象：无法获取 Pod 指标，Dashboard 显示 CPU/内存为 -。
  • 原因：DaoCloud 镜像站未收录该镜像（返回 403），且缺少 TLS 跳过参数。
  • 解决：改用阿里云镜像 registry.cn-hangzhou.aliyuncs.com/google_containers/metrics-server:v0.7.0，并添加 --kubelet-insecure-tls 启动参数。
